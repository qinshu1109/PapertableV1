# Papertable 需求域边界 v0.1

- 生效日期：2026-08-03
- 状态：生效中的可修订基线
- 作用：约束需求职责、数据归属和跨域业务接口
- 不代表：代码目录、进程、数据库或部署单元必须按此拆分

## 判断依据

当前真实活跃项目「有效需求分析」已有 15 张卡片、14 条关系边和 23 次完整运行；三种正式分支关系均被使用，23 次运行全部冻结资料范围并实际检索/读取，用户已确认 3 条金子和 1 条墓碑。正式知识发布尚无实际使用记录。

因此先确认三个用户价值需求域；Agent、SSE、HTTP、SQLite、供应商配置和 MemOS 同步仍视为实现或支撑能力。正式知识发布保留为候选能力，有真实使用后再判断是否形成独立需求域。

## 价值边界

- 用户：琴疏；当前不引入多人协作复杂度。
- 问题：线性聊天难以持续探索，大量 AI 输出普通且难以核验。
- 结果：围绕授权资料进行非线性探索，淘汰普通输出，保留并复用用户确认的有效判断。
- 不做：通用聊天平台、自动批量写笔记、多用户系统。

## 三个需求域

| 需求域 | 负责 | 数据与规则的唯一归属 | 不负责 |
|---|---|---|---|
| 可信资料求证 | 绑定与索引项目资料、冻结运行范围、检索读取、受控引用、证据不足拒答 | 资料库、文档、片段、运行及来源快照、readableIds/readIds、引用资格、回答终态 | 卡片关系、判决生命周期 |
| 非线性知识探索 | 项目内卡片、深挖/发散/改道、概念卡、会话与上下文继承、路径导航 | 项目标识、卡片、边、会话、分支上下文及继承规则 | 引用有效性、模型协议、判决真值 |
| 判断沉淀与复用 | 金子、墓碑、确认、放弃、替代，以及向后续回答提供当前有效判断 | 判决、判决状态、替代关系、远端记忆身份 | 回答证据门禁、自动发布正式知识 |

一条业务规则只能归属一个需求域；同一业务数据只能有一个真值源。其他域只能通过业务接口使用它们。

## 跨域业务接口

| 服务接口 | 提供者 | 使用者 | 说明 |
|---|---|---|---|
| 提交探索问题 | 非线性知识探索 | 可信资料求证 | 提交当前项目、卡片上下文与用户问题，发起一次可审计求证 |
| 返回可信回答 | 可信资料求证 | 非线性知识探索 | 返回完成、拒答或失败终态，以及可核验引用 |
| 登记用户判断 | 非线性知识探索 | 判断沉淀与复用 | 将用户选中的回答或改道关系登记为金子或墓碑候选 |
| 提供有效判断 | 判断沉淀与复用 | 可信资料求证 | 为新一次求证提供已确认且未被替代的判断；相关性由模型按本轮问题自行判断，引用必须显式标注 |

这里定义的是业务接口的 Why、What 与约束。HTTP、SSE、函数调用、SQLite 表和 MemOS 工具只是实现这些接口的系统方案，不反向决定需求域边界。

## TASK 必填字段

从本基线生效起，每张新 TASK 必须在标题信息中填写：

```markdown
- 主需求域：可信资料求证 / 非线性知识探索 / 判断沉淀与复用
- 业务接口：接口名；纯域内变更填“无（域内）”
- 数据真值源：本任务读取或修改的领域实体；无数据变更时明确写“无”
- 质量约束与验收终态：本任务不能破坏的约束，以及可验证的完成状态
```

执行规则：

1. 一张 TASK 只指定一个主需求域；跨域协作写进“业务接口”，不另造综合模块。
2. 新需求无法归属时，先用用户价值和真实场景修订本页，再写代码。
3. 只有发现真实重复规则、错误归属或反复跨域修改时，才整理被触及的代码；不预先搬目录、拆服务或增加抽象层。
4. 需求域若不能独立说明用户价值、核心数据和质量约束，就与相邻域合并；只有出现独立价值和持续变化压力时才继续拆分。
