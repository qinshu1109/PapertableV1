# 任务：为我的 Memos 笔记产出「受控标签词表」草案

## 你要做的事

通读我 Memos 里的全部笔记（约 500 条短笔记），产出一份**受控标签词表草案**，写到 `/Users/qinshu/Documents/papertableV1/docs/TAG-VOCABULARY-draft.md`，等我人工审定。之后会有另一个任务按审定词表批量打标签——本任务只出词表，不打标、不写库。

## 数据源（只读）

SQLite 库：`~/Library/Application Support/memos/memos_prod.db`，**只读打开，禁止任何写操作**。

读取口径（与镇纸 pw-notes.ts 一致）：

```sql
SELECT uid, content, created_ts, payload
FROM memo
WHERE row_status = 'NORMAL'
ORDER BY created_ts;
```

- `created_ts` 是 unix 秒；`payload` 是 JSON，tags 在 `$.tags`。
- 必须全量通读，分批读（每批 50–100 条），**禁止抽样**后就开始写。

## 词表规矩（违反任何一条都要返工）

1. **标签总数 ≤ 20 个**。超了说明你在凑，合并再合并。
2. 每个标签必须给：名称 / 一句话定义 / **2 个逐字真实例子**（从笔记原文抄片段 + 标注笔记日期，禁止编造或改写）/ 估计覆盖笔记数。
3. **同义必须合并**：镇纸、Paperweight、paperweight 是同一个标签；英文中文混用时以中文为主标签名。
4. 允许 Memos 风格的层级标签（如 `镇纸/协作台`），但层级只许两层。
5. **宁缺毋滥**：预计大量笔记（流水、链接、一句话）什么标签都不打，这是正常的。**禁止设「其他」「杂项」这类垃圾桶标签**。
6. 笔记里含有卡密、交易、链接等敏感内容：**不为这类内容立标签**，例子引用时避开密钥/卡密明文，并在草案末尾「不建议打标的类别」一节如实列出。
7. 打标签的目的是「以后捞得回来」：想象三个月后我想找「关于 XX 我当时记了什么」，词表是为这个服务的，不是为了分类而分类。
