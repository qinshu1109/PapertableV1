# TASK-024 卡片回收站列表页（能看、能还原、能彻底清空）

- 状态：done（2026-08-03 实现并实测通过）
- 主需求域：非线性知识探索
- 业务接口：无（域内）
- 数据真值源：卡片、运行、关系边的真值在服务端 SQLite（`pt_cards`/`pt_runs`/`pt_run_events`/`pt_run_sources`/`pt_edges`）；`trashedCards` 只是 localStorage UI 覆盖层，不是数据；`pt_verdicts` 本任务只读检查、不修改
- 质量约束与验收终态：运行中的卡片不可物理删除；被任何判决（`pt_verdicts.card_id`）引用的卡片不可物理删除；物理删除不可逆，UI 必须显式二次确认；还原只改覆盖层、不触碰服务端；`npm run verify` 通过

## 背景

2026-08-03 用户清理验收测试卡片时误把全部卡片移入回收站。事实核查：「移入回收站」只是 localStorage 覆盖层 `papertable-ui-overlay.trashedCards`（本地隐藏，服务端不物理删除），数据无损。但产品唯一的恢复手段是删除后 6 秒内的撤销 toast——误操作无法挽回。同时存在相反诉求：测试产生的零散卡片需要一个真正的删除出口。

## 问题级需求

- 用户需要看见回收站里有什么，而不是一个黑箱。
- 误删后能随时找回，不限 6 秒。
- 确认无用的卡片能真正删掉，不在库里越积越多。

## 五类最小需求单元

### 业务功能

1. 回收站列表：侧栏入口显示当前项目被隐藏卡片的数量，打开列表弹窗，逐张显示标题。
2. 还原：单张还原与全部还原，只从 `trashedCards` 移除，卡片重新出现在卡片树中。
3. 彻底删除：单张彻底删除与清空回收站，调用服务端物理删除；二次确认后执行。
4. 服务端 `purgeCards`：按项目物理删除卡片，外键级联清掉运行、运行事件、运行来源与关系边；逐张校验，返回已删与跳过清单。

### 业务数据

| 数据 | 唯一归属/用途 |
|---|---|
| 卡片、运行、边 | 服务端 SQLite，物理删除的唯一作用点 |
| `trashedCards` | localStorage 覆盖层；还原/隐藏的唯一状态 |
| `pt_verdicts.card_id` | 删除保护的唯一判定来源，只读 |

### 质量场景

1. **防误删**：被任一判决引用（含 proposed 墓碑草稿）的卡片返回 skipped 并说明原因，不删除。
2. **防中断**：卡片有 status='running' 的运行时返回 skipped。
3. **不可逆操作有门槛**：彻底删除与清空回收站在 UI 上需要二次确认。
4. **一致性**：物理删除后覆盖层同步移除 id，当前打开的卡片被删时导航到存活卡片。
5. **项目隔离**：purge 只作用于当前项目的卡片。

### 业务接口

无（域内变更）。`POST /api/projects/:id/cards/purge` 是域内系统接口，不是跨域业务接口。

### 业务报表

无。回收站列表本身是操作界面，不是报表。

## 实现要点

- 后端 `src/projects.ts` 新增 `purgeCards(store, projectId, cardIds)`；`src/main.ts` 新增 `POST /api/projects/:id/cards/purge`，返回 `{ purged, skipped: [{ cardId, reason }] }`。
- 前端 `api.ts` 新增 `purgeCards`；`store.tsx` 新增 `restoreCards` / `purgeCards` 动作；`ProjectSidebar` 底部新增回收站入口（带计数）；`Dialogs.tsx` 新增 `TrashDialog`（列表 + 还原 + 彻底删除 + 清空，二次确认）。
- selfcheck 增加：级联删除、判决引用跳过、运行中跳过、项目隔离。
- 已知残留（不做）：卡片对应的 Pi 会话记录留在会话存储中，不随物理删除清理；项目级删除仍为占位。

## 明确不做

- 不做项目级删除（保持现有防误删提示）。
- 不做回收站保留期、自动清空、多设备同步覆盖层。
- 不修改 `pt_verdicts`；不为被引用卡片提供"强制删除"。
- 不做服务端回收站表——`trashedCards` 继续只是覆盖层。
