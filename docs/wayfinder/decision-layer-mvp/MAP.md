## Notes

- 项目：镇纸 Paperweight（本仓库 papertableV1）。触发源：2026-08-07 用户脑暴——AI+Obsidian 笔记翻不动 / 笔记软件接微信要会员且双层入口分散 / MCP skills 装多装少都分散注意力 / 看图看趋势要另一个工具；提出三层架构：本地文件=原料层 → 纸桌=过滤层（产金子/墓碑/决策链）→ 镇纸=决策层（可视化直观对比、收拢多入口注意力）。
- 目的地烤问五问已关票（详见「Q00 目的地烤问」）：Q1 决策对象=A 内容生产（协作台升级版），知识笔记服务于 A 非独立决策域；Q2 收拢入口=A 零硬接入（AI 直读本地文件，说话即输入，flomo/微信硬接入出范围）；Q3 对比形式=D：A 候选并排比证据=心脏最优先，C 多笔记/多公开数据源直观可视化排第二，B 草案vs现状后续；Q4 金子墓碑=C 弹药架+AI 上下文双通道互为校验（deepseek 漏标 100% 前科，"AI 用了人看不见"单走不可行）；Q5 多源可视化块=A 进第一刀。
- 默认锁定（用户未反对）：协作台=升级非另起；MCP/skills 管理痛出范围（agent 配置问题非屏形式）。
- 与既有规格的关系：《协作台 Harness 目标效果规格》v1（docs/SPEC-collab-harness-effect.md，已验收）是协作台 v1 的效果层共识，本图是它向「决策层 MVP」的升级——核心句（筛选降负、AI 不做决定）、推式大屏、防平庸三条（原文原则/异类保留/判断留人）全部延续。
- 多源可视化块原型（2026-08-07 用户看过 ASCII 原型后拍 Q5）：容器+可插视图，三视图各答一个业务问题——①来源对比（哪里的料最出选题）②主题矩阵（同一主题跨来源证据分布：评论引文×金子×墓碑×笔记×押注）③产出榜（哪个来源该加该断：被引用次数/产出候选数）。
- 关键文件：`frontend/src/pw/Collab.tsx`（协作台屏现状）、`src/pw-sieve.ts`（候选卡）、`src/pw-verdicts.ts` 与 `src/verdicts.ts`（判决与金子）、`src/pw-corpus.ts`（语料）、`evals/sieve/`（筛子评测集）。
