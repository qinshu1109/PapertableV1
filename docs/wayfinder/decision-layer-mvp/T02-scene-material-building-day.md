## Question

走查「素材制作日」在决策层 MVP 屏上的用户旅程：押注之后，素材草案/大纲在屏上的位置、弹药架怎么供料（哪条金子该进哪份草案）、多源可视化块在素材场景里有没有用。沿用 T01 的走查方法与格式，结论同样喂给「F01 决策层 MVP 形式规格」。

## Resolution

—— 走查记录（逐步追加，关闭时汇总）——

**S1 草案的家（2026-08-08 用户看过 A/B 双版 ASCII 参考图后拍板 B）**：**待你定队列只放新候选**（第一眼干净）；素材草案/大纲**挂在在途押注卡下**，押注卡角标显示「📝有草案×N」，点开才见才定。代价确认：「哪张押注下压着没定的草案」靠角标提示，不靠队列混排。默认补充（用户未反对）：顶条待你定计数拆成「候选 N + 草案 M」两项分开计，草案数不进队列但计数可见。

**S2 草案怎么来（2026-08-08 用户拍板 A，附质量四件套）**：**押注成立即自动起草**——挑卡转押注 → AI 自动出草案挂卡下等定（草稿制，否了不亏；指定押注可说一句拉黑）。用户追问"自主必然平庸，除金子/墓碑/决策链外还能怎么抬高草案预期、喂 skills 还是 prompt"——kimi 定调并被认可（"认，继续"）：**skills/prompt 不是主药**（通用能力=通用输出=平庸的数学本质；平庸是判断依据不够不是能力不够），**质量四件套**：①喂用户的判断痕迹作对照证据（否过的候选卡与草案=最强口味信号、押注三行、改稿 diff）②产 N 份互相对照的草案+人挑（贴热点/贴少数派/反共识，复用候选卡挑改否结构，AI 从"写好"变"摆散盘"）③否掉的草案做成 bad case 集回流，prompt/模型改动前后跑分对比（沿用 PW-29 套路）④易平庸字段（挂钩点/标题/开头）AI 只给候选不给定稿。**关键解扣：发动方式不影响草案预期，影响预期的是产的时候有什么对照证据、产几份。**

**S3 草案长什么样（2026-08-08 用户补约束后拍板）**：约束=**每天过一次或数次的决策流程，必须好判断、好决策、减少深度**。定案=**三份对照·首屏只露"路子+标题候选"各一行**（贴热点/少数派/反共识三行菜牌，扫三行挑路子），**骨架（5-7 行大纲节点+对照证据标）点开才见**（先看路再看货）；否的是路子整批否，不逐行审稿。份数默认三、随口可调。深度=大纲非逐字稿（沿用早前"'成品'暂定为大纲"拍板）。论证：有对比才有锚（一份得自己憋哪里不对更费脑）；全露骨架=阅读爆炸（Obsidian 老路）；与候选卡"极简三样"同脾气——第一屏只摆够下判断的最少东西。

**S4 弹药架供料（2026-08-08 用户拍板 A）**：**只标金子引用（落库）**——草案哪段用了哪条金子，段旁标"§N"，点开看原件、引用落库计数（吃 T01 引用落库）。**墓碑不进成稿**：起草输入端带着避（AI 写时绕开），成稿不宣告"我避了"——屏上每个标都必须能当场验真，"避让"无法自证不上屏；墓碑约束力放在起草输入端保证。

**S5 定稿与收尾（2026-08-08 用户拍板 A）**：**定稿=产出物挂载到押注卡**——大纲定稿挂到押注卡产出物位（沿用现有挂载/摘除通路），押注继续在途，看结果日照常结账；制作/发布/直播在 agent 窗口干（与抓+筛同规矩）。素材制作日收工并入 T01 收工小结（定了几份草案也进"今天定了什么"）。默认锁死（用户未反对）：**否掉的草案进 bad case 集**（四件套③）；**改稿改前改后 diff 落库**（四件套①口味信号）。

**走查结论（关票）**：素材制作日在决策层屏上的一天——①草案的家：挂在在途押注卡下（角标📝×N），待你定队列只放新候选，顶条计数拆「候选 N + 草案 M」；②草案怎么来：押注成立自动起草（草稿制可拉黑）+**质量四件套**（喂判断痕迹对照证据[N 份里贴热点/少数派/反共识]、否掉进 bad case 集回流、易平庸字段候选制、改稿 diff 落库；定调：skills/prompt 非主药，发动方式不影响预期）;③草案形态：三份对照·首屏只露"路子+标题候选"各一行，骨架（5-7 行节点+对照证据标）点开才见，份数默认三可调，深度=大纲；④弹药架供料：只标金子引用（段旁 §N+落库），墓碑起草输入端避、成稿不宣告；⑤定稿收尾：产出物挂载押注卡，押注在途照常结账，收工并入 T01 收工小结。**新建清单追加（喂 F01）**：素材草案体系（草案表挂押注卡/三份对照/路子+标题候选行/骨架/对照证据标/bad case 集/改稿 diff 落库）、自动起草发动（押注成立触发可拉黑）、定稿挂载产出物。
