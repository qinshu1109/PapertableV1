- 已决方向（2026-08-04 charting 共识）：
  1. 目的地形态 = 一页纸效果规格（非实施方案）
  2. 四类筛选成本全收：读评论 / 读数据 / 找金子 / 跨期对比
  3. 推式起点：AI 提前筛好摆出，人从「看」开始；可视化大屏
  4. 协作台 = 今日值得看大屏 + 同屏对话深挖；大盘屏不动（长期复盘分工）
  5. 触发 D：数据到达即筛为主 + 打开兜底补筛；扳机唯一、产物仅大屏内容、不写正式表
  6. 聚合入口：一屏看全部在途押注今日动态；单卡深挖，对话按卡隔离
- 纪律：铸币权在人（押注/结账/金子只人确认）；摆证据 √ 下结论 ×（逐场景校准）；每会话只解一票（research 除外）；引用用名字不用编号
- 防平庸条款（2026-08-04 用户拍板，原则级）：AI 自主决策只会产出平庸选题/方向（Papertable 的初衷即对抗 AI 惯性输出的 99% 平庸）。平庸不在「推荐」字样里，在压缩动作里（归堆/概括/挂钩点=向均值回归）；机会藏在长尾异类。三条停线：①原文原则——引文/证据一律原文，AI 不改写不概括；②异类保留——每轮必摆少数派/长尾区，不强行归堆；③判断留人——归类命名、方向、挂钩点由人下刀（挂钩点是最易平庸的字段）。筛子角色=搬运工/摆盘工，不是厨师。
- 场景走查三步格式：触发 → AI 筛掉什么/摆出什么（图表形态）/停在哪 → 人一眼看到什么/做什么决定
- 技能：grilling（场景走查与决策票）；工单类型规则见 `~/.kimi-code/skills/wayfinder/SKILL.md`
- 关键文件：`docs/PRD-Paperweight.md`、`docs/TASK-PW-15-collab-harness.md`、`src/pw-collab-tools.ts`、`src/pw-collab.ts`、`src/pw-corpus.ts`
- 商业背景（2026-08-04 用户披露，目的层总纲）：做内容的目的是销售不是粉丝。变现两通路：①cozai.net 自建中转站（人群=用 AI 工作的办公族/程序员；私域粉丝群引导使用，阻力最小，前提先有粉丝）；②Papertable/Paperweight 达预期后直播展示「用 vs 不用」的差距，结果导向（直播开发日志太枯燥不做）。
- 定位重构（2026-08-04 用户拍板）：**Paperweight = 内容生产的工作台，不是事后复盘数据的马后炮项目**。无严格意义"潜在买家"——内容使命是把路人变买家：覆盖"了解并使用 AI 但不知道用 AI 做什么"的人群，销售性质 + 普及型统一。协作台场景集按内容生产链重排，押注/结账等复盘导向机制定位待重估。
