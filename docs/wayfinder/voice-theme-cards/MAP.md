## Notes

- 触发源：2026-08-11 用户指出语料评论直接展示原文，评论量级数千不可能逐条看，希望像笔记屏 PW-63 概念卡那样展示。
- 现状数据：`pw_corpus_docs` 4 个视频各 79-100 条评论（抓取上限 100/视频），右栏 like 降序 top50 逐条 + 单条收录（PW-46/47）。视频一多、抓取放宽即是几千条的墙。
- 既有漏斗（不动）：语料评论 → 收录进声音列表（PW-26 自动分拣挂钩）→ 提请候选（PW-45）→ 协作台挑改否。本刀只改入口的展出与收录单位。
- 店规兼容性：主题卡 = 弹药架「严格引用层」同构（PW-63 已验证）——上面 AI 摆盘、下面逐字原文当场验真；收录动作仍是人按，单位从单条变主题。
- 评论与笔记的唯一新信号：**赞数**（参与度）。聚合输入按赞降序截断（≤300 条），卡面把赞数摆出来当证据强度。
- 关键文件：`src/pw-voice-promote.ts`（收录/提请）、`src/pw-corpus.ts`（`readPwCorpusComments` 只读）、`frontend/src/pw/Voice.tsx`（右栏现状）、`src/pw-miner.ts`（PW-63 聚合模式参照）。

## Decisions so far

- [Q00 语料评论分区烤问](Q00-destination-grilling.md) — 三问关票：拍板单位=主题卡+逐字证据（赞数进证据面）；卡出口=整卡收录走既有声音表+自动分拣，弃=重聚不再浮出；触发=手动「聚一下」按视频聚/重聚，不做自动。
- [Q01 主题卡方向修正](Q01-sieve-pivot.md) — 用户验收否决主题卡（还是太长太多、一次性全量分析过拟合出平庸桶）：改拍思路一「AI 做筛子不做摘要」——逐条判噪音、信号条轻量标签分组、逐字证据；skill 驱动不做后台 Harness；PW-64 卡面留作台账对照。
