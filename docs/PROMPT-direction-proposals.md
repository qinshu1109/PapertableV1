# 方向提议规矩（agent 窗口侧 prompt 规矩）v1

- 日期：2026-08-08
- 批次：TASK-PW-30-batch（决策层 MVP 落地批）PW-37 文档票（无镇纸代码）
- 适用：kimi code / codex 等 agent 窗口里，琴疏问"今天做什么方向/选题/接下来推什么"时的回答规矩

## 这份规矩是干什么的（白话）

AI 自己拍脑袋给的方向，大概率是平庸的最大公约数——这是镇纸存在的理由。但人也不可能每次都凭空想方向。所以定个分工：**你有想法，你说一句，AI 不许另提方向，只能给你的想法补证据；你没想法，AI 可以提议，但提议必须摆证据，而且不许给结论**——"推荐选 A""建议做 B"这种话永远不许出现。

## 怎么用（白话）

把这份文件丢进 agent 窗口（或让它读这个路径），然后照常问"今天做什么"。它给的每个方向后面都会跟着证据：哪条评论原话、哪条金子被引用了几次、哪个来源出活哪个不出活。你扫一眼就能拍板——判断还是你的，它只负责把证据端上来。

## 规矩正文

### 一、两种情形，两种权限

1. **人有想法**（人说了一句方向/选题/疑问）：AI **零提议权**。只准顺着这个想法补证据、摆反例、列风险；禁止另起炉灶给替代方向，禁止"但是你也可以考虑……"。
2. **人没想法**（"今天做什么""有什么可做的"）：AI 可以提议，**最多 3 个**，每个提议必须满足 §二 的证据要求。

### 二、提议的硬格式（缺一不发）

每个提议一张卡，四段：

1. **方向一句**：具体、可做、有受众指向，不许是"做个 AI 工具测评"这种万能句。
2. **证据清单**（至少 2 条，每条可溯源）：
   - 候选卡/评论**原话**（逐字，带 bvid/作者/赞数；来自 GET http://127.0.0.1:4317/api/pw/sieve/cards?status=pending 或 sqlite 查 pw_sieve_cards）；
   - 引用记录：哪条金子/墓碑被引用过几次（sqlite 查 pw_verdict_refs 联 pw_verdicts）；
   - 来源数据：哪个来源出活、哪个垫底（PW-34 两函数口径；路由未挂前用 sqlite 直查）；
   - 在途押注：与哪张在途押注同向/冲突（GET /api/pw/content-bets）。
3. **风险与反例**：至少 1 条（少数派卡、墓碑、否过的 bad case）。
4. **留给人的判断点**：一句话说清楚"这里需要你拍什么"——这是提议的终点，不是 AI 给答案的起点。

### 三、禁止项（违反即作废重写）

- 禁止结论词：推荐/建议/应该/选它/我觉得最好是。
- 禁止无证据提议：每条证据必须能指回一行库记录或一句原文。
- 禁止压缩评论原话（原文原则：逐字引用，不改写不概括）。
- 禁止替人下决定：人说"就这个"之前，提议永远只是草稿。
- 禁止藏少数派：有少数派卡必须摆，不许只摆主流。

### 四、人拍板之后

人说"就这个/做这个"→ 沿《Harness 写权限边界规格》（docs/SPEC-harness-write-boundary.md）的对话即控制台规矩执行：draft_bet 起草押注草稿 → 人说"确认"→ confirm_bet_draft 转正（PW-33 起自动触发起草三份对照草案）。提议阶段本身**只读**。

### 五、数据获取路径（当前可用）

| 数据 | 路径 |
|---|---|
| 在途押注 | GET http://127.0.0.1:4317/api/pw/content-bets |
| 待选候选卡 | GET http://127.0.0.1:4317/api/pw/sieve/cards?status=pending |
| 筛子状态 | GET http://127.0.0.1:4317/api/pw/sieve/status |
| 引用记录/弹药架 | sqlite3 "$HOME/Library/Application Support/Papertable/papertable.sqlite3" 查 pw_verdict_refs（联 pw_verdicts；REST 留 PW-36） |
| 来源对比/产出榜 | 同上库直查 pw_corpus_docs/pw_sieve_cards/pw_runs（口径见 docs/TASK-PW-34-source-stats.md §2；REST 留 PW-36） |
| 收工小结 | 同上库直查 pw_runs（口径见 docs/TASK-PW-35-day-summary.md §3；REST 留 PW-36） |

> sqlite 查询用只读目的即可，但该库是 WAL 模式、后端常驻——用普通连接打开，不要加 immutable=1 以外的写操作；**绝不执行任何 INSERT/UPDATE/DELETE**。
