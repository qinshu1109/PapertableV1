# 镇纸 Paperweight 决策层 MVP 形式规格 v1

- 状态：**草稿，待用户验收**（2026-08-08 起草；wayfinder effort：`docs/wayfinder/decision-layer-mvp/`）
- 决策来源：Q00 目的地烤问五问、R01 数据资产盘点、T01 选题调研日走查、T02 素材制作日走查、T03 可视化口径，全部用户逐票拍板

## 这刀是干什么的（白话）

把镇纸从"协作台"升级成你的**决策层**：所有要你拍板的事——选题候选、素材草案、在途押注——都汇到这一层屏上。AI 把证据摆好、把草稿写好，你扫一眼就定。
治的是这几个痛：AI 写的笔记几百条翻不动；Obsidian、flomo、微信、各个 AI 窗口来回切；看数据还得开别的工具。

## 怎么算好（白话）

一天过几次、每次几秒钟：打开屏，"待你定队列"里新候选并排摆着证据，AI 引用过的金子原话在旁边架子上，你扫完就挑/改/否。收工有一份"今天定了什么"的小结。
全程不用翻笔记、不用开第二个工具、不用盯 AI 干活——它在 agent 窗口干活你看得见，这层屏只摆**能定的事**。

---

以下给干活的看，可以跳过。

## 1. 定位与边界

- **决策对象=内容生产**（选题候选/押注/素材）。知识笔记经纸桌过滤成金子/墓碑/决策链后，作为弹药服务内容决策——**不是独立决策域**。
- **零硬接入**：不接 flomo/微信/Obsidian 账号。AI 直读本地文件（Obsidian 库=本地文件夹，不要密钥/会员）；用户在任何 AI 窗口说的话就是输入。
- **执行面 vs 决策面**：抓+筛、起草、制作发布在 **agent 窗口**（codex/kimicode 等）执行，过程在那边看（也是直播镜头所在）；**镇纸屏=决策面，只展示可供决策的结果，不为过程再造 Harness 监控**。
- **升级关系**：本规格是《协作台 Harness 目标效果规格》v1（已验收）的升级。延续：核心句（筛选降负、AI 不做决定）、推式大屏、防平庸三条（原文原则·异类保留·判断留人）、写权限边界（对话即控制台）。
- **秒级约束**：本层屏的所有判断动作必须秒级——第一屏只摆"够下判断的最少东西"，深度全部收进点开/hover 之后。

## 2. 屏块（MVP 第一刀）

### B1 待你定队列（第一眼，推式工作台）

- 内容：新候选卡 + AI 干了活等发话的草稿/代办，时间倒序。
- 顶条计数拆两项：「候选 N + 草案 M」。素材草案不进队列（挂押注卡下），但计数可见。

### B2 候选对比区（心脏）

- 候选卡**并排**比证据，取代逐张翻。
- 每卡**极简三样**：逐字引文 + 来源（谁说的/多少赞/出自哪条视频）+ 少数派标记。规模/挂钩/新鲜度/排序分收进 hover 或点开。
- 排序：排序分降序；少数派虚线金框单独成区，不与普通卡混排。
- 评论原文回看：`bvid`+`rpid` 拼 B 站锚点链接（voice 卡除外）。

### B3 弹药架（使用证据栏）

- **严格引用层**：只摆 AI 在对话/草案里**实际引用过**的金子/墓碑原件（原话 + "AI 于何时引用"）。
- 检索全走封装好的 **MemOS 混合检索**；屏上**不放**"检索命中·未引用"层。
- 校验逻辑：AI 说用了没上屏=造假穿帮；架空但回答有金子影子=漏标现场，靠人抓+提示词契约。
- 配套新建：**引用落库**——AI 每次标注引用，持久化「引用→判决 id→消息/草案 id」（补 R01 缺口①；引用计数、退役层、产出榜的地基）。

### B4 多源可视化块（容器+可插视图，第一刀两视图）

- **①来源对比**（下次抓数据往哪抓）：每来源的评论数、候选卡数、少数派数、金子数、入决策链数。第一刀来源只有 B 站视频（真实数据）；书/文章/笔记行待来源通路后补（R01 缺口③）。
- **②产出榜**（哪个来源该加、哪个该断）：产出候选数、被挑数、被引用次数；垫底又不出活的=该清的注意力信号。
- **主题矩阵留雾**：AI 后台暗线打主题标签（进库不进屏），攒够覆盖且抽查靠谱后再开。
- 口径：出卡率=候选数/评论数；**入决策链=候选被挑/金子被引用/草案被定稿三类事件合计**；时间范围默认**近 7 天**，可切 30 天。

### B5 对话条

- 沿用协作台：全局对话（层1）+ 按卡深挖（层2）；对话指认四规不变；写权限边界（对话即控制台）不变。

## 3. 素材草案（挂押注卡下）

- **发动**：押注成立即自动起草（草稿制，否了不亏；指定押注可说一句拉黑）。
- **形态**：三份对照（贴热点/少数派/反共识）。**首屏只露"路子+标题候选"各一行**；骨架（5-7 行大纲节点+对照证据标）点开才见。份数默认三、随口可调。深度=**大纲**，非逐字稿。
- **供料**：只标金子引用（段旁 §N+落库，点开验原件）；**墓碑起草输入端避、成稿不宣告**（屏上每个标必须当场验真，"避让"无法自证不上屏）。
- **定稿**：产出物挂载到押注卡（沿用现有挂载/摘除通路），押注继续在途，看结果日照常结账。
- **质量四件套**：①起草时喂用户判断痕迹作对照证据（否过的候选卡与草案、押注三行、改稿 diff）②N 份对照散盘（AI 摆散盘不写好）③否掉的草案进 **bad case 集**回流（prompt/模型改动前后跑分对比，沿用 PW-29 纪律）④易平庸字段（标题/挂钩点/开头）AI 只给候选项，不给定稿。
- 定调：**skills/prompt 不是质量主药**（通用能力=通用输出）；发动方式（自动/发话）不影响草案预期，预期靠对照证据+散盘+评测。

## 4. 方向发起（选题调研）

- **有想法**：人说一句"今天看看 XX"，AI 去找视频、抓、筛，料进队列叫人。AI 零提议权。
- **没想法**：AI 依弹药架+在途押注+多源可视化（哪个方向料少/哪个主题没人碰）**摆证据**提议几个方向候选，人挑/换/否。**提议必须摆证据，不给结论。**

## 5. 收工小结

- 一天结束一份「今天定了什么」：挑了几张/否了几张/押了哪几注/定了几份草案/AI 代办了几件（吃引用落库+审计账本）。
- 用途：直播"用和不用差距"的现成素材；可一键发给 agent 窗口存档。

## 6. 数据口径与已知缺口

- 候选卡 12 字段+批次头全现成（`pw_sieve_cards`/`pw_sieve_runs`）。
- 金子/墓碑实体：镇纸 `pw_verdicts`（本地真值）+ 纸桌 MemOS（远端真值）+ `pw_gold_mirror`（只镜金）。
- 时间字段全表 TEXT ISO，近 7 天过滤可算；评论级时间粒度只有语料级（ctime 在磁盘，第一刀容忍）。
- **第一刀容忍的缺口**：①主题维度（暗线攒，矩阵留雾）②书/文章/笔记来源通路（语料只有视频，来源对比先只有视频行）③镇纸金子被引用次数（引用落库新建后补齐）。

## 7. 新建清单（九项）

1. 待你定队列聚合视图（候选+待发话草稿，计数拆两项）
2. 并排对比区极简三样改造（含少数派单独成区、hover 收起其余）
3. 弹药架引用层 + 引用落库
4. 收工小结
5. 方向提议（agent 窗口侧摆证据行为）
6. 多源可视化块（容器+来源对比+产出榜）
7. 素材草案体系（草案表挂押注卡/三份对照/路子行/骨架/对照证据标/bad case 集/改稿 diff 落库）
8. 自动起草发动（押注成立触发，可拉黑）
9. 定稿挂载产出物

## 8. 反例段——这层屏不是

- **不是仪表盘**：不追求全景展示，事找人不人找事。
- **不是过程监控**：不播 AI 干活流水（过程在 agent 窗口看）。
- **不是相关猜测栏**：弹药架只摆实际引用，不摆"可能相关"。
- **不是通用创作平台**：只服务用户自己的内容生产链，链外功能不聚合。
- **不是逐字稿编辑器**：草案深度=大纲，判断永远秒级。
- **AI 不是厨师**：AI 搬运/摆盘/起草；归类命名、方向、挂钩点、挑改否，全由人下刀。

## 9. 范围外（本图不覆盖）

- flomo/微信硬接入；知识笔记独立决策域；MCP/skills 管理面板（agent 配置问题）。
- 主题矩阵上屏（暗线攒）；时间趋势维度（发布后有回流再凝）；B 类对比（草案 vs 现状）进屏。
- 押注台/结账等既有屏块的归并；app 内建筛子后台管线与 agent 窗口发动面的角色重估（雾）。
- 大盘屏任何改动（既有纪律）；模型选型。
