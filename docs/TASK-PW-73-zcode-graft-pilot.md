# TASK-PW-73：ZCode 速记嫁接试点（智能助手一道全做）

## 一句话说明（业务意图）

你每记一条笔记，AI 当场拿你的旧笔记和记忆跟你碰一碰——嫁接在「记笔记」这个动作上，不做每日定时捞料（召回）。试点的真机入口只有一个：飞书「琴疏的智能助手」（cli_aa1a，入站由 ZCode 独占，已勘察确认无抢消息）。

## 主需求域

内容生产（笔记通路/速记入口）。跨域消费：判断沉淀与复用域的 MemOS 记忆只做**只读检索**，不产生写入。

## 业务接口

- 入口：飞书「琴疏的智能助手」p2p 文本 → ZCode bot（唯一入站消费者）。
- 笔记写入：memos 官方 HTTP API（连接参数在 `~/Library/Application Support/Papertable/feishu-relay.json`，0600，含 memosUrl/memosToken；回报与文档中禁止出现 token 明文）。
- 记忆检索：MemOS MCP（用户确认 ZCode 已配，实施时先核实可用）。
- 镇纸后端（4317）与本仓库代码：**本 TASK 零改动**。PW-72 通知链路、feishu-relay（cli_a946，用户明确不修）一律不碰。
- 种子出口：人工搬运（用户自己把有价值的种子拿到 dsh/纸桌），本期不做自动搬运。

## 数据真值源

- 笔记真值源：memos（ZCode 只经官方 API 写入，失败必须显式回报）。
- 记忆真值源：MemOS（只读）。
- 入口配置真值源：`~/.zcode/v2/` 下 ZCode bot 配置（改动前先备份原文件）。

## 质量约束与验收终态

ZCode 收到一条 p2p 文本后的人格契约：

1. **先写后发散**：先调 memos API 把原文写成一条笔记（带「速记」标签，沿用 relay 旧惯例）；写失败必须明说"没写成"，禁止假装已写。
2. **发散卡格式**：1~3 条旧笔记/记忆**原文摘录**（不改写不概括）+ 一句"为什么相关" + 一个钩子问题。摆原文、不给结论、判断留人。
3. **沉默权**：没有合格关联就回「记下了，没捞到相关的」，禁止硬凑。
4. **终验（用户真机）**：手机飞书发一条测试速记 → memos 里出现该条 → 同一聊天里收到发散卡或沉默回执。三项齐才算过。

试点度量（跑 20 条或一周后再看，不在本 TASK 内建仪表）：回应率 + 废话率。
