## 逐刀四字段

### PW-30 引用落库与弹药架

- 主需求域：判断沉淀与复用
- 业务接口：提供引用记录（新接口，供本批 PW-34/35/36 消费）
- 数据真值源：新表 `pw_verdict_refs`（引用 → verdict id → 消息/草案 id → created_at）；只读消费 pw_verdicts、pw_collab_messages；不改写任何既有表
- 质量约束与验收终态：AI 回答/草案中的 §N 标注解析后**幂等落库**（同一消息重处理不重复计）；伪造/未知 §N 不计入（沿纸桌 verdict_use 纪律：绝不拿 provided 冒充 used）；弹药架读函数只返回**实际引用过**的 verdict + 次数 + 最近时间；mock 单测 + 真实对话冒烟（说一句让 AI 引用金子 → 库里落一笔 → 弹药架读出它）；verify 全绿

### PW-31 素材草案体系

- 主需求域：内容生产
- 业务接口：无（域内新数据）
- 数据真值源：新表 `pw_drafts`（bet_id 挂押注卡 / 路子 / 标题候选 / 骨架节点 JSON / 状态 draft→finalized·rejected）；改稿 diff 落库（改前改后全文）；bad case 集 = rejected + 理由可查询
- 质量约束与验收终态：状态机单向不可逆；草案必须挂押注卡（无孤儿断言）；PW-19 押注卡既有行为与测试全绿；verify 全绿

### PW-32 起草管线

- 主需求域：内容生产
- 业务接口：提供有效判断·生产侧（金子墓碑装配 + §N 标注）；提供选题候选（读候选卡）
- 数据真值源：写 pw_drafts（PW-31）；读 pw_bets / pw_sieve_cards / pw_verdicts / 否过的卡与草案（判断痕迹）；写 pw_verdict_refs（PW-30）
- 质量约束与验收终态：**质量四件套落实**——①装配喂判断痕迹（否过的候选卡与草案、押注三行、改稿 diff）②三份对照散盘（贴热点/少数派/反共识三路子，只出大纲不出口吻定稿）③易平庸字段（标题/挂钩点/开头）只给候选项 ④深度 = 大纲 5-7 行节点；墓碑只进输入端避让、成稿不宣告（断言产出无"已避开墓碑"类字样）；§N 标注经 PW-30 落库；否掉的草案进 bad case 集，prompt/模型改动前后可重跑对比（沿 PW-29 评测纪律）；mock 单测 + 真实模型冒烟（对真实库一张押注卡起草：三份路子各行其是、骨架 5-7 行、§N 落库笔数对得上）；verify 全绿

### PW-33 自动起草发动与定稿挂载

- 主需求域：内容生产
- 业务接口：登记内容执行（定稿产出物挂载沿用既有通路）
- 数据真值源：pw_drafts 状态流转；新表 `pw_draft_blacklist`（指定押注拉黑不起草）；pw_artifacts 挂载沿用
- 质量约束与验收终态：押注成立（confirm_bet_draft / pick_sieve_card）自动触发起草（草稿制，否了不亏）；拉黑的押注不触发（测试断言）；发动失败不影响押注成立本身（兜底留痕）；定稿 → 产出物挂载押注卡沿用 PW-03 通路，押注继续在途；发动/定稿落 pw_runs 审计事件；verify 全绿
