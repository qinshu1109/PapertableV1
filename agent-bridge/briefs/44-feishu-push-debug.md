## 排查顺序（先 API 侧，再 App 侧，最后系统侧——别一上来就让用户翻设置）

1. **会话内可见性（关键分叉）**：让用户打开手机飞书「琴疏的智能助手」会话，数里面有没有这 21 张测试卡（1 张验证卡 + 20 张矩阵卡）：
   - 有 = 消息投递正常，断在**推送通道**（大概率）；
   - 没有 = 断在**消息可见性**（小概率，但要从这里分叉）。
   - 你也可以用 API 佐证：`GET /open-apis/im/v1/messages/:message_id`（拿日志里的 message_id）看消息状态。
2. **会话免打扰**：机器人会话被设过免打扰则不弹横幅。引导用户检查该会话设置；如有 API 可查会话/用户侧状态就用 API。
3. **飞书 App 内设置**：新消息通知总开关、锁屏通知、通知音。
4. **安卓系统层（国产 ROM 头号嫌疑）**：通知渠道细分（飞书在系统里可能有多个通知类别，个别类别被关）、电池优化/后台限制（MIUI/EMUI/ColorOS/OriginOS 都会杀后台）、自启动权限、锁屏后清理。飞书在国内无 FCM，靠厂商推送通道，通道要 App 存活或厂商通道注册成功才收得到。问用户手机品牌型号，按对应 ROM 给设置路径。
5. **文档核实**：查飞书开放平台文档——自建应用机器人消息的推送机制、interactive 卡片与普通 text 在推送上的差异、有没有 push 相关字段/限制（比如 `urgent` 加急接口的适用边界）。
6. **必要时加试**：发 1 张**普通 text 消息**（不是卡片），排除「卡片类型不触发推送」的可能。
