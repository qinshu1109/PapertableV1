# 13 · 召回事件账本：浏览器验收（codex）

## 背景

「笔记召回事件账本」一期已落地：后端新表 `pw_recall_events` + 四个出口打点（claude 完成，370/370 测试绿），前端在镇纸「笔记」屏新增「账本」页签（kimi 完成，build 通过、headless 截图自检通过）。后端服务已重启，活接口 `GET /api/pw/recall-events/summary?days=30` 正常返回。

账本口径：摆出(surfaced) 只能由系统/AI 记；确认(confirmed)/拒绝(rejected)/挂接(attached)/用上(used)/结账(settled) 只能来自人的动作。used 一期没有入口，恒 0 属正常。

## 验收清单

入口：http://127.0.0.1:4317/ → 右下角切「镇纸」→ 顶部导航「笔记」→ 屏内页签「账本」（在 大盘/树图 之后、全部笔记 之前）。

1. **页面渲染**：账本页正常显示：说明文字、「近 7 天 / 近 30 天 / 近 90 天」切换、漏斗（摆出→确认→挂接→用上→结账）、分通道表（收工回响/捞料候选/笔记树/结账 × 六档）、「最近事件」区。当前真库可能全 0，全 0 不是 bug——空态文案应为「还没有事件——账从下一次摆出/确认开始记。」
2. **范围切换**：点「近 7 天」「近 90 天」，数字随范围变化（全 0 时表现为说明文字里的天数变化），无报错、无白屏。
3. **端到端真实动作**（关键）：去「笔记→树图」或「大盘」，做一次**真实的人动作**——例如在树图把一条笔记挂到某个押注（attach），或在大盘确认/拒绝一条捞料候选。然后回到「账本」页签，确认：对应通道的 挂接/确认/拒绝 计数 +1，「最近事件」出现该行（时间、事件、通道、笔记 uid、押注、角色），漏斗数字同步。动作做完若不想留痕，可在原界面撤销/拒绝，但**撤销动作本身也应再记一行事件**——这也是验收点。
4. **只读红线**：账本页本身不得有任何写按钮（没有确认/删除/修改入口），它只是账。
5. **接口直查**（可选）：`curl http://127.0.0.1:4317/api/pw/recall-events?limit=10` 与页面最近事件一致；`days=999` 应返回 400。
