# 协作台 Harness 目标效果规格 v1（草稿，待验收）

- 来源：wayfinder 地图 `docs/wayfinder/collab-harness-effect/`（2026-08-04 建图，T01/T02 走查、R01/R02 调研完成）
- 状态：v1 草稿。验收通过 = 地图完成；实现任务拆分（PW-XX）另起 effort，不在本规格。

## 0. 核心句

**AI 的职责是降低重复劳动的筛选成本、降低认知负担，让人更聚焦地做决策；AI 不做决定。**

定位：镇纸 Paperweight 是**内容生产的工作台**，不是事后复盘数据的马后炮项目；协作台是它的生产现场。

## 1. 商业语境（一切判据的总纲）

- 做内容的目的 = 销售，不是粉丝。变现两通路：cozai.net 中转站（用 AI 工作的办公族/程序员，私域引导，阻力最小，前提先有粉丝）；Papertable/Paperweight 达预期后直播演示「用 vs 不用」的差距。
- 内容使命：把「了解并使用 AI、但不知道用 AI 做什么」的路人变成买家。普及型 + 销售性质天然统一：**产品主张 = 内容主题 = 人群痛点**（过滤无用信息，让 AI 干正事）。

## 2. 协作台形态

- **推式起点**：AI 提前筛好摆好，人从「看」开始，不从「问」开始；可视化大屏呈现。
- 协作台屏 = 「今日值得看」大屏 + 同屏对话深挖区；**大盘屏不动**（长期复盘分工）。
- **聚合入口**：一屏看全部在途押注的今日动态；点进单卡才钻取明细；对话按卡隔离（一次只深谈一张卡）。

## 3. 两种 run

- **筛子 run（后台，新增）**：扳机 = 数据到达（服务端路由收口：sync created>0 / corpus done / 人工录入 / voice 四线，去抖合并 + watermark 轮询崩溃兜底，按行 UUID 去重）+ 打开协作台发现新数据未筛时当场补筛。产出 = 大屏草稿内容，不写任何正式表。会话 cron 缺席的日子 = 当日无新筛（接受）。
- **对话 run（前台，PW-15 改造）**：顺大屏疑点深挖；权限表静态化延续（只读 allow / 起草 draft / 结账 deny 即 schema 不存在）。

## 4. 停线（纪律）

1. **排序 √ 推荐 ×**：候选按证据强度排序（依据印在卡上可复核）；任何卡面不出现「推荐」字样。
2. **草稿制**：AI 一切产出（候选卡、结构、草案）是草稿——可改、可推翻、可全否重出；AI 不定稿。
3. **铸币权在人**：押注、结账、金子只由人确认；AI 对正式表无写权限。
4. **防平庸三条**（原则级）：AI 自主决策只会产出平庸（99% 惯性），平庸在压缩动作里（归堆/概括/挂钩点=向均值回归），机会藏在长尾——
   - **原文原则**：引文/证据一律原文，AI 不改写、不概括；
   - **异类保留**：每轮必摆少数派/长尾区（归不进堆的、反常识的、少数人说但说得狠的），不强行归堆；
   - **判断留人**：归类命名、方向定夺、挂钩点写法由人下刀（挂钩点是最易平庸的字段）。
   - 筛子角色 = 搬运工 + 摆盘工，永远不掌勺。

## 5. 场景走查（已决）

### 5.1 选题调研（T01）

- 触发：带着模糊方向找证据；一轮人工筛选量级约几千条。
- 筛子目标：捞「路人用 AI 的真实困惑」。每条困惑 = 一个选题候选（内容 = 演示 Paperweight 解决该困惑）。
- 产出：一轮 5~8 张选题候选卡，四字段——**困惑引文**（评论原文，痛是真的）/ **规模感**（同类困惑出现范围，痛的人多）/ **工具挂钩点**（可演示的差距，你能治）/ **新鲜度**（为什么现在做）。
- 人的动作：挑 / 改 / 否（全否 = 换方向重筛，也是有效产出）。
- 挑中去向：转成**内容押注卡**——演示哪个困惑 / 要什么转化信号（加群、问工具、求链接）/ 哪天看结果。押注机制保留，押的对象从播放量换成路人转化。

### 5.2 素材制作（T02）

- 最重劳动：把证据包排成叙述结构 + 设计演示（用 vs 不用怎么演）。挑料、写稿不重。
- AI 产出：2~3 个完整候选结构（料已摆进格子，如痛点先行/结果先行）+ 演示对照步骤草案（左列「不用时」右列「用时」，每步挂实据）。
- 停线：草稿制（用户明确认同）。
- 成品（暂定）：**大纲**——人把草案改成大纲定稿。

### 5.3 现阶段出范围

T03 直播准备、T04 发布后转化回看（一个视频未发）。第一期内容真发出后另起 effort 恢复。

## 6. 用户旅程（参考叙事）

第一天 23:00 沙发上撂下一个模糊方向、授权抓取 → 夜里数据落库、筛子自醒（读几千条、归堆、数规模、挂演示点）→ 次日 8:00 大屏 6 张候选卡按证据排好，同屏追问「这些吐槽什么语气」→ 挑/改/否，挑中转成内容押注卡 → 下午「开始做素材」：两个候选结构 + 对照步骤草案，改成自己的话定稿大纲 → 之后每天数据一到自动补筛，打开永远是最新。
对比现状：从「空聊天框想该问什么」变成「摆好的大屏上挑、改、否」——几千条筛选 = 一眼、一指、一改。

## 7. 反例段（不想要什么）

1. AI 自己结账 / 改金子 / 写任何正式表（铸币权）。
2. 没读到数据就编数字；引用不给原文。
3. 「问一句答一句」的客服式聊天框（无推式、无大屏）。
4. AI 味概括、AI 腔归堆命名（防平庸条款 1/3）。
5. 长尾异类被强行归堆或丢弃（防平庸条款 2）。
6. 大屏信息过载——变成另一种「要读的东西」（候选卡限 5~8 张即为此）。
7. 卡面出现「推荐」字样（停线 1）。

## 8. 数据可及性要求（R01 事实底座）

筛子必须读到现状 8 工具读不到的：语料评论**全文**与视频 stat、落盘 meta/comments、data_docs 版本链历史、verdict 证据链（evidence_doc_ids/来源押注/时间）、连接与同步状态（connections/runs）。已知坑：`read_voice` 不过滤 dropped（已丢弃声音会被当有效引用），筛子层必须修；评论 rpid/ctime/replies 入库被丢弃，全量只在磁盘 jsonl。字段级清单见 R01 工单。

## 9. 扳机与运行（R02 事实底座）

唯一扳机 = main.ts 路由层落库成功返回后的统一收口（四线）；进程内去抖队列为主 + DB watermark 轮询为崩溃兜底；到达判定按行（doc UUID，sync 无幂等键、批次无整体事务）；语料卡 fetching 需人工 force 解锁（低频接受）。全文见 R02 工单。

## 10. 明确不在本规格

实现任务拆分（PW-XX）与排期；模型选型、图表库/前端技术选型；大盘屏改动；T03/T04 场景；AI 对金子/结账/正式表的写权限（永远 deny）。
