## 判断依据

当前真实活跃项目「有效需求分析」已有 15 张卡片、14 条关系边和 23 次完整运行；三种正式分支关系均被使用，23 次运行全部冻结资料范围并实际检索/读取，用户已确认 3 条金子和 1 条墓碑。正式知识发布尚无实际使用记录。

因此先确认三个用户价值需求域；Agent、SSE、HTTP、SQLite、供应商配置和 MemOS 同步仍视为实现或支撑能力。正式知识发布保留为候选能力，有真实使用后再判断是否形成独立需求域。

v0.2 新增依据：2026-08-03 用户确认 Paperweight（镇纸）产品方向（见 `PRD-Paperweight.md`）——内容创作场景存在真实闭环：选题押注 → 执行（做视频/直播/发布）→ 平台数据回流 → 到期结账。执行挂载、平台数据源连接、低频同步与人工接手、数据文档回流这组职责有独立用户价值（让押注有结果可结账）和独立数据（数据源连接、同步任务、产出物挂载、回流数据文档），既有三域无法自然归属，故立为第四需求域「实践与数据回收」。

v0.3 新增依据：2026-08-04 用户拍板 Paperweight 定位 = 内容生产工作台（《协作台 Harness 目标效果规格》v1 验收通过，见 `docs/SPEC-collab-harness-effect.md` 与 wayfinder 地图 `docs/wayfinder/collab-harness-effect/`）——选题调研与素材制作存在真实用户价值（把几千条原始语料筛成少数可拍选题与素材草稿，降低筛选成本与认知负担），有独立数据（选题候选卡、素材草案/大纲、内容押注卡、筛子运行审计），既有四域无法自然归属（非判决沉淀、非执行回收），故立为第五需求域「内容生产」。

## 价值边界

- 用户：琴疏；当前不引入多人协作复杂度。
- 问题：线性聊天难以持续探索，大量 AI 输出普通且难以核验。
- 结果：围绕授权资料进行非线性探索，淘汰普通输出，保留并复用用户确认的有效判断。
- 不做：通用聊天平台、自动批量写笔记、多用户系统。

一条业务规则只能归属一个需求域；同一业务数据只能有一个真值源。其他域只能通过业务接口使用它们。

## 跨域业务接口

| 服务接口 | 提供者 | 使用者 | 说明 |
|---|---|---|---|
| 提交探索问题 | 非线性知识探索 | 可信资料求证 | 提交当前项目、卡片上下文与用户问题，发起一次可审计求证 |
| 返回可信回答 | 可信资料求证 | 非线性知识探索 | 返回完成、拒答或失败终态，以及可核验引用 |
| 登记用户判断 | 非线性知识探索 | 判断沉淀与复用 | 将用户选中的回答或改道关系登记为金子或墓碑候选 |
| 提供有效判断 | 判断沉淀与复用 | 可信资料求证 | 为新一次求证提供已确认且未被替代的判断；相关性由模型按本轮问题自行判断，引用必须显式标注 |
| 登记实践执行 | 判断沉淀与复用 | 实践与数据回收 | 已押注（带验证指标、数据来源、结账日）的判决交给执行侧，开始挂载产出物并跟踪数据 |
| 回流数据文档 | 实践与数据回收 | 判断沉淀与复用 | 发布后的平台数据形成可引用的数据文档，供到期结账裁决引用；需检索时经可信资料求证的既有索引消费，不另建索引 |
| 提供语料与回流数据 | 实践与数据回收 | 内容生产 | 筛子只读消费全量语料（评论原文/视频 stat/落盘文件）、数据文档版本链、连接与同步状态；不改写任何回收侧数据 |
| 提供有效判断（生产侧） | 判断沉淀与复用 | 内容生产 | 选题与素材讨论中引用已确认金子墓碑（§N 显式标注），支撑「这坑我栽过没有」的对照 |
| 提供引用记录 | 判断沉淀与复用 | 内容生产 | 判决被 AI 实际引用的流水（谁引用、何时、引到哪条消息/草案），供弹药架、产出榜、收工小结只读消费（v0.5） |
| 登记内容执行 | 内容生产 | 实践与数据回收 | 内容押注卡（演示困惑/转化信号/看结果日）确认后交执行侧挂载产出物、跟踪转化信号 |
| 提供选题候选 | 内容生产 | 判断沉淀与复用 | 筛子产出的选题候选卡（草稿）供对话深挖引用、协作台屏展示；只读消费，卡片状态流转（挑/改/否）归内容生产 |
| 提供笔记读取 | 实践与数据回收 | 内容生产 | 只读消费外部笔记库（Memos）条目全文/标签/创建时间并附回链，供回顾捞取、节奏统计与第七屏展示；不改写笔记库（v0.6） |
| 提请选题候选 | 实践与数据回收 | 内容生产 | 观众声音原文逐字提升为候选卡草稿（回收侧回写 promoted_to_draft_id 防重、已丢弃/噪音拒绝；生产侧走既有挑/改/否，不另立状态机）；语料评论一键收录进声音后同样可走本提升链（v0.8） |
| 回写笔记摘要 | 实践与数据回收 | 非线性知识探索 | 人确认后的卡组决策链摘要经 Memos 官方 HTTP API 写为一条笔记（带标签、幂等防重），真值留 Memos，本地只记审计；不碰 Memos SQLite 只读纪律（v1.2） |

这里定义的是业务接口的 Why、What 与约束。HTTP、SSE、函数调用、SQLite 表和 MemOS 工具只是实现这些接口的系统方案，不反向决定需求域边界。

## TASK 必填字段

从本基线生效起，每张新 TASK 必须在标题信息中填写：

```markdown
- 主需求域：可信资料求证 / 非线性知识探索 / 判断沉淀与复用 / 实践与数据回收
- 业务接口：接口名；纯域内变更填“无（域内）”
- 数据真值源：本任务读取或修改的领域实体；无数据变更时明确写“无”
- 质量约束与验收终态：本任务不能破坏的约束，以及可验证的完成状态
```

执行规则：

1. 一张 TASK 只指定一个主需求域；跨域协作写进“业务接口”，不另造综合模块。
2. 新需求无法归属时，先用用户价值和真实场景修订本页，再写代码。
3. 只有发现真实重复规则、错误归属或反复跨域修改时，才整理被触及的代码；不预先搬目录、拆服务或增加抽象层。
4. 需求域若不能独立说明用户价值、核心数据和质量约束，就与相邻域合并；只有出现独立价值和持续变化压力时才继续拆分。
