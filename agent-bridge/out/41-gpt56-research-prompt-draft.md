# 给 GPT-5.6-Pro 的跨领域研究 prompt：镇纸激活阻力与每日推送链路（草稿 v1）

> 状态：草稿，等简报 41（grok 事实调研）回来后合并事实层再定稿。
> 结构与密度对齐 `~/.kimi-code/skills/cross-domain-research/references/example-notes-loop.md`。

````
我在维护一个本地个人知识/判断工作台，遇到一个"系统已建成但主人不用"的激活断环问题。
在我自己的领域（笔记软件 / PKM / 个人工作台）里找到的方案全是给漏水的船打补丁，
所以我来找别的领域有没有早就解决过同构问题的——请把这当一次跨领域研究来做。

【我的坑，如实描述】
我花了数周建成一套个人系统（下面有结构说明），功能不少：每日 AI 自动捞料、押注台、
笔记洞察、观众声音分析，全部跑在本机。但真实数据是：建成以来我几乎没主动打开过它。
理由很平庸：琐事太多，想不起来；想起来了，"打开一个网页看看"这个动作本身阻力就很大。
系统里所有的好东西都是"拉式"的——我不去，它不来。

我直觉上的候选补丁是搭一条"每日推送链路"：用我已在用的 agent 运行时
（deepseek-harness，插件制）写一个插件，每天定时读取我经飞书速记进笔记库（Memos）
的新笔记，生成摘要/洞察，推送到我手机并弹起系统通知；推送结果同时落在系统的
可视化大屏上；其中模糊的、AI 容易误解的问题或方向，自动路由到系统的"梳理区"
等我有空时结构化澄清。我怀疑这还是在打补丁：它假设"不打开"的原因是"没触达"，
但可能真正的原因是"打开了也没有非看不可的东西"——推送只会把这个缺陷放大，
甚至加速我对通知的免疫。

【系统背景，供你定位结构】
我的系统是两个产品、同一仓库、同一数据库，分工明确：
- 纸桌 Papertable（思考场）：负责「意图 → 想法 → 选题」的探索与求证——项目、卡片、
  求证、把已确认的判断标成"金子"。"把纸摊开让你想。"
- 镇纸 Paperweight（判断闭环工作台）：负责「押注 → 开干 → 数据回流 → 结账」——
  押注台、金子墓碑库、笔记的捞与判、观众声音都在这里。"把纸压住让你定。"
- 两端经「金子同步」单向焊接：纸桌确认的金子流入镇纸作为可复用资产。
- 笔记写在外部速记工具（飞书 → Memos 速记库）里，镇纸只读，真值留外部库。
- agent 运行时是 deepseek-harness（dsh），插件制；已拍板的分期计划是把镇纸的
  「看与引用」能力做成 dsh 插件（P0 只读问答 → P1 定时推送进独立面板 → P2 通知收口）。
  这是既定方向，不用重议；本研究只补"每日推送与激活"这一层的事实与机制。
- 铁律：AI 摆证据、不下结论、不替我做任何状态变更；写操作只有"AI 起草→我确认"
  和"我亲手点"两种。这条不可协商。
- 我在做的内容方向是"玩 AI"直播，笔记和押注大多围绕选题与判断。手机是 iOS，
  国内网络环境（部分境外推送服务不可用或延迟大）。

【我要你研究的问题】
1. 同构检索：人类历史上哪些领域面对过"工具/系统已建成，但主人不用、想不起来用"
   的激活问题，并且真的把"被动触达→主动使用"转化做起来了？候选：健康管理/健身
   App 的推送召回、Duolingo 式 streak 与提醒、日记/冥想 App 的习惯养成、企业 BI
   的日报邮件/晨会大屏、CRM 的销售跟单提醒、newsletter/晨报的固定节奏、Readwise
   式每日回顾邮件、智能家居的被动告警 vs 主动查询、GitHub contribution graph。
   请验证哪些真同构、哪些只是表面像，并补充我没想到的领域。
2. 机制提炼：被验证的机制里，"把主动打开变成被动触达、再把触达变成一次有效使用"
   是怎么实现的？推送时机与频率、推送内容的颗粒度（摘要？一条最值钱的？到期提醒？）、
   通知疲劳与静默期、streak/损失厌恶、通知内直接行动（不回主 App 就完成动作）、
   渠道选择（邮件/系统通知/IM 机器人），各自的前提条件和失败模式是什么？
3. 补丁定位：我的候选链路（定时读笔记→摘要→手机弹通知→大屏展示→模糊问题路由
   梳理区）放在这些机制里属于哪一类？它的致命假设是什么？有没有我从类比里看不到
   的第三条路（比如不推送，而是把"打开"嫁接到我已有的每日动作上）？
4. 度量：激活类问题该用什么指标衡量健康？推送→打开转化、打开→行动转化、通知
   关闭率、7/30 日回访、还是别的？我目前没有任何激活指标，只有"库存/条数"类
   生产指标——这个盲区本身是不是问题的一部分？
5. AI 分工边界：铁律是 AI 摆证据、人下判断。在一条自动推送链路里，"今天推哪条
   笔记/哪个押注到期该提醒"这个选择动作，在上述领域的实践里通常被当作筛选
   （合规的"摆"）还是决策（越权）？有没有成熟的边界划法？
6. 与纸桌/镇纸结构的咬合：推送链路的"分拣"端（什么值得推）和"澄清"端（模糊问题
   路由去梳理）应该落在纸桌、镇纸、还是 dsh 插件层？从其他领域的机制看，哪种咬合
   最不容易在两周后被我本人废弃？

【输出要求】
- 每个问题先给判定再给依据；依据落到具体领域实践、方法名或文献，不泛泛而谈。
- 明确指出我描述里的错误假设——比如"不打开是因为没触达"本身是不是错误诊断？
  有没有领域认为个人工具的低频使用其实健康？指出我漏掉的坑比回答问题更重要。
- 关键反问请直接塞进回答，例如："推送内容质量不过关时，推送是不是在加速流失？"
- 最后给一张"如果只能改一处"的候选清单，只摆证据和取舍，不替我下结论。
````
