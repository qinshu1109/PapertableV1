# batch-llm-sieve：批量 LLM 逐条筛选

对大批量条目做「有无信息量」的逐条判定＋固定桶分组，产出逐字证据报告，让人基于原文下判断。AI 是筛子：只分流，不概括、不改写、不替人决定。

## 一、核心立场：AI 做筛子，不做摘要

- 每条输出只有三件事：唯一 id、keep（true/false）、桶标签。不归堆、不写总结句、不命名主题、不改写原文。
- **不许一次性全量分析**：再短的列表也按批逐条判——整块喂入会让模型输出「回归均值」，平掉个体差异。
- 排序用元数据（热度、赞数、时间）不参与判定，只看内容；每条独立判断，不互相参照。

## 二、固定桶：桶集合事先定死

- 开跑前定死桶集合（桶名＋一句话「装什么」），写进任务卡；执行中**禁止发明新桶**。
- 噪音类别同样预定义（例：广告引流、无信息玩梗、纯表情复读、与主题无关灌水）；噪音条不给桶标签。
- 事先指定一个兜底桶，拿不准的进兜底桶，不新建桶。
- 为什么定死：桶集合一漂移，批与批不可比，归组统计全部作废。

## 三、批间 prompt 逐字相同

判定口径全文写死在 skill/任务卡里，每批**逐字照抄**，禁止执行中即兴改写——口径变了，前后批不可比，审计无从对照。骨架：

```text
你是筛子。逐条判断条目有没有信息量：只删减，不概括、不评价、不替人决定。
只输出 JSONL，每行 {"id":…,"keep":true|false,"tag":"桶名"}。
判噪音（keep=false，不给 tag）：<预定义噪音类别，逐字列出>。
判有信息（keep=true，tag 必填）：<固定桶清单，逐字列出>；拿不准进 <兜底桶名>。
<排序元数据名>不参与判断，只看内容。每条独立判断，不互相参照。
```

## 四、规模分档

| 量级 | 跑法 |
|---|---|
| 百级（≤200 条） | 单 agent 直判：自己读全量输入，按口径逐条判，直接写报告 |
| 千级以上 | 主代理切批＋并发子代理 map-reduce（标准跑法，见下） |

千级 map-reduce 流程：

1. **切批**：按行号/序号确定性切批（约 50 条/批），列批清单（批号 → id 范围）。
2. **map**：并发派子代理，每个子代理只拿自己那批原文＋同一份判定口径（逐字照抄），只返回 JSONL 判决行。**分波派发，每波并发 ≤8**，跑完一波再发下一波；每批产出先落盘（如 results/batch-NN.jsonl）再进下一波。实测教训：一次性派 32 个并发会把主代理回合跑断、map 零产出——并发上限是踩坑校准值，不是保守估计。
3. **对账**：主代理收齐后验——返回 id 全集＝输入 id 全集，无重无漏；任何一批没返回或条数对不上 → **重派那批**，不许跳过、不许拿部分结果凑数。
4. **reduce**：主代理只看「id＋桶名＋排序键」归组，不把原文倒回自己上下文；组内按排序键降序。
5. **写报告**：按三层密度（见六）；对账行写清「输入 N / 判出 N / 重派 K 批」。

## 五、覆盖对账（硬要求）

- 唯一 id 无重无漏：输出 id 集合与输入 id 集合完全相等。
- 信号数＋噪音数＝输入总数。
- **对账行写进报告头部**，如：「输入 1024 条 / 判出 1024 条 / 信号 411＋噪音 613 / 重派 2 批」。
- 噪音条也要列全（报告末尾噪音区，供人翻案）——筛子只分流，不销毁。

## 六、报告三层密度

数字是统计，句子必须是逐字摘录，零 AI 概括：

1. **30 秒层（桶卡目录）**：头部（输入规模、执行方式、署名、对账行）＋一行一桶：`桶名 | 条数 | 排序键合计 | 该桶最高排序键条目的首句逐字摘录 ≤40 字`，空桶写「空」。这层是导航，让人 30 秒决定进哪几个桶。
2. **3 分钟层（正文）**：桶按排序键合计降序，每桶只摆 top N（如 top 3）逐字条目；单条过长只留首句，末尾补 `…[全文 N 字，见附录]`；每条带作者/时间/id 等定位信息。
3. **深潜层（附录，独立文件）**：全部信号条目逐字全文按桶分组、组内降序。任何量级都走「正文 top N、其余附录」，不按量级变通。

## 七、产出先落文件，入库强制对账

- 执行产物＝判决 JSONL（逐批落盘）＋报告 md（＋附录 md），先落文件，再谈入库/采信。
- 结果要进正式系统（数据库、展示层）时，由**入口系统强制复核对账**：唯一 id 无重无漏、信号＋噪音＝总数，**不过即拒**（如 HTTP 400 不落库）。对账从执行方自律升级为入口强制——报告可以写错，入口不放行错账。

## 八、跑前检查清单（照抄）

- [ ] 桶集合（含兜底桶）与噪音类别已写死在任务卡
- [ ] 判定口径 prompt 全文就绪，map 阶段逐字照抄
- [ ] 唯一 id 字段确认（没有就先生成序号 id）
- [ ] 量级判档：>200 条走切批 map-reduce，每波并发 ≤8
- [ ] 每批产出落盘路径约定好
- [ ] 报告含对账行＋噪音区＋三层密度（正文 top N＋附录全文）
- [ ] 入库入口有强制对账，不过即拒

## 出处

方法论源自 Papertable「观众声音」评论筛子实践（skills/voice-comment-sieve，B 站评论百级/千级多次实跑，四方对照验证逐条判定对模型不敏感），以及镇纸后端导入接口的强制对账门。50 条/批、每波并发 ≤8、正文 top 3 等参数均为实跑校准值。
