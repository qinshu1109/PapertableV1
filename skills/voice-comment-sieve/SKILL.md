# voice-comment-sieve：语料评论筛子

把一个语料视频的评论**逐条**判噪音（不平整、不概括、不命名主题），信号条按**固定桶**分组，输出逐字证据报告。人看报告判断；AI 不替人收录、不替人弃。

## 纪律（违反即返工）

- 语料库与 papertable.sqlite3 **只读**；本 skill 不写任何 app 数据，产出只有 Markdown 报告。
- 逐条判断是机械活：不归堆、不写总结句、不命名主题。**不许一次性全量分析**——再短的评论列表也按批判断（防输出回归均值）。
- 模型不限定（四方对照证明逐条判断模型不敏感），成本可忽略；但每桶/每批 prompt 必须逐字相同（防批间漂移）。
- 报告末尾必须附噪音区（翻案用）+ **覆盖对账行**（rpid 无重无漏、信号+噪音=输入总数）。

## 固定桶（8 个，逐条扔进去；不许发明新桶）

| 桶 | 装什么 |
|---|---|
| 对比 | 工具/模型/方案之间的比较 |
| 价格 | 计费、额度、订阅、值不值 |
| bug反馈 | 具体故障、异常行为 |
| 功能 | 功能评价、功能建议、功能咨询 |
| 求助 | 使用求助、选型提问、网络/兼容性问题 |
| 场景 | 「我在用 X」、使用现状陈述 |
| 建议 | 给 UP 主的评测建议、内容建议、评测质疑 |
| 评价 | 夸赞/吐槽等纯态度但确有所指（非玩梗） |

噪音（不进桶）：广告引流、玩梗无信息、纯表情/复读、与视频内容无关的灌水。
拿不准的进「评价」桶，不许新建桶。

## 执行方式（按量级三选一）

### ① 百级（≤200 条）：单 agent 直判

agent 自己读 comments.jsonl，按判断口径逐条判，直接写报告。参照四方对照试跑（2026-08-11，codex/Claude 窗口均验证过）。

### ② 千级以上：主代理切批 + 并发子代理（map-reduce，标准跑法）

1. **切批**：主代理按行号确定性切批（每批 50 条），列出批清单（批号 → rpid 范围）。
2. **map**：并发派子代理，每个子代理只拿自己那批原文 + 同一份判断口径 prompt（下节，逐字照抄）。子代理返回 JSONL：`{"rpid":N,"keep":bool,"tag":"桶名"}`。**分波派发，每波 ≤8 个并发**，跑完一波再发下一波；每批产出先落盘 `results/<bvid>/batch-NN.jsonl` 再进下一波（2026-08-11 实测：一次性派 32 个并发会把主代理回合跑断，map 零产出）。
3. **对账**：主代理收齐后验——返回 rpid 全集 = 输入全集，无重无漏；任何子代理没返回/条数对不上 → 重派那批，不许跳过。
4. **reduce**：主代理只看「rpid + 桶名 + 赞数」归组（不把原文再倒回上下文），组内按赞降序。
5. **写报告**：照下节格式；对账行写清「输入 N 条 / 判出 N 条 / 重派 K 批」。

## 判断口径 prompt（map 阶段逐字照抄，审计用）

```text
你是镇纸评论筛子。逐条判断评论有没有信息量：只删减，不概括、不评价、不替人决定。
只输出 JSONL，每行 {"rpid":数字,"keep":true|false,"tag":"桶名"}。
判噪音（keep=false，不给 tag）：广告引流、玩梗无信息、纯表情/复读、与视频内容无关的灌水。
判有信息（keep=true，tag 必填八桶之一）：对比/价格/bug反馈/功能/求助/场景/建议/评价。
赞数不参与判断，只看内容。每条独立判断，不互相参照。
```

## 报告格式（三层密度阶梯：零 AI 概括——数字是统计，句子是逐字摘录）

1. 头部：视频号/标题、UP主、输入总条数、信号条数与桶数、噪音条数、执行方式（①/②/③）、生成时间、署名（执行体+模型）、**对账行**。
2. **桶卡目录**（30 秒层，紧接头部）：一行一桶，全 8 桶按总赞降序——`桶名 | 条数 | 总赞 | 该桶最高赞评论的首句（逐字摘录 ≤40 字，超了截断加 …）`。空桶写「空」。这层是导航，让人 30 秒决定进哪几个桶。
3. 「信号评论」区（3 分钟层）：桶按总赞降序，**每桶只摆赞数 top 3 逐字**；单条超 ~120 字只留首句，末尾补 `…[全文 N 字，见附录]`；每条 = 「逐字原文（或截断首句）」 — @作者 · N 赞 · 月/日 · rpid:xxx。
4. **附录文件**（深潜层，独立 md）：全部信号评论逐字全文按桶分组、组内赞降序，**不按量级变通，任何量级都走「正文 top3、其余附录」**；被截断评论的全文以附录为准。
5. 末尾「噪音区」：每条 = [rpid] 前40字 — @作者 · N 赞，必须列全。

## 跑完回话口径

报告路径 + 信号/噪音条数 + 桶数，三行内回给调用方；不要复述报告全文。

## 跑完导入 papertable（PW-65，可选但推荐）

报告写盘后，把判决结果导入镇纸观众声音页（右栏三层密度视图的数据源）：

```bash
curl -X POST http://127.0.0.1:4317/api/pw/voice/sieve-runs/import \
  -H 'Content-Type: application/json' \
  -d '{"bvid":"<BV号>","resultsPath":"<判决 jsonl 目录，含 batch-*.jsonl>","commentsPath":"<评论源文件，.json 爬虫格式或 .jsonl 均可>","reportPath":"<报告 md 路径>","provider":"<执行体，如 claude-code 子代理编组>","model":"<模型>","reassigned":<重派批数>}'
```

- 后端会强制复核对账（rpid 无重无漏、信号+噪音=总数），不过就 400 不落库——对账从 skill 自律变成后端强制。
- 语料未注册时自动从 commentsPath 补录进 data/corpus/；已注册则复用。
- 导入成功后告诉用户「观众声音页右栏已可看」。
