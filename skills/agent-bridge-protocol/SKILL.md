# agent-bridge-protocol：文件桥多 agent 协作协议

多个 agent（不同产品、不同窗口、不同模型）围绕同一个仓库协作时，把「派单—执行—回报—验收—交接」全部落成仓库内的普通文件。凡能读写文件的 agent 都能参与；一切决定与产出事后可查。

## 一、何时用文件桥，何时不用

用文件桥，当以下条件成立（通常同时成立）：

- **异步**：派单方与执行方不同时在线，任务以小时/天计，不需要毫秒级往返。
- **可审计**：事后要能回答「谁派的、依据什么、谁做的、验收凭什么通过」——文件即档案。
- **跨产品**：参与者是异构 agent（不同厂商 CLI、不同 harness、脚本），唯一公共能力就是读写文件。

不用文件桥，当：任务需要同步结构化返回值、低延迟多轮工具调用，或单一 harness 内已有内建的子代理/委托机制——那是实时编排的领地，文件桥不替代它。两者可并存：实时通道递话，文件承载规格与产物。

## 二、目录约定

```text
<bridge-root>/
  GUARDRAILS.md        守门红线：哪些文件/动作任何 agent 不得自行改动（常驻，所有简报默认引用）
  briefs/NN-主题.md    派单简报，编号递增；只有派单方写
  out/                 执行产物：报告、进度文件；文件名由简报指定
  qa-evidence/         验收证据：截图等，命名 NN-场景-状态.png（NN＝对应简报号）
  HANDOFF-<任务>.md    交接文档：换人/换窗口接手用，自包含
```

## 三、编号简报：结构模板

每份简报假设**执行者零上下文**：不依赖任何会话历史，从简报第一行读起就能干活。骨架（照抄改内容）：

```markdown
# 简报 NN：一句话主题（任务性质：开发，写代码 / 探索，只读出报告 / 验收，只验不改）

先读 <bridge-root>/GUARDRAILS.md，红线默认生效。

- 发起方/主控：<谁派单，从哪个通道盯进度>
- 执行方：<哪个 agent/窗口>
- 日期：YYYY-MM-DD
- 依据：<上游报告/决定的文件路径，如有>

## 背景（你没有任何上下文，从这里读起）

<局面、为什么做、真值源文件路径清单>

## 规格

<做什么、怎么算对：接口/数据结构/状态机用表格写死，别让执行方猜>

## 红线与只读区

<本任务不许碰什么；哪些目录只读、哪些可写>

## 验收清单（自行跑完再回报）

- [ ] <测试命令全绿>
- [ ] <真实运行输出贴原文>

## 回报口径

<改动文件清单、测试命令与结果、输出摘录；产物类报告写到 out/ 下简报指定的文件名>

## 分工边界

<哪些事明确不归执行方，归谁>
```

三条要点：

- **红线引用**：每份派活简报开头一句引守门文件。红线单独常驻、简报只引不抄——改红线只改一处，旧简报不会过期。
- **验收清单自跑**：执行方自己跑完清单才有资格回报；「自报通过 ≠ 验收通过」，独立验收另有简报（见五）。
- **判定标准写死即受保护**：验收标准写进简报后就是守门物，执行 agent 不得修改检查/验收定义来让自己「通过」（此条应进红线文档本身）。

## 四、执行方纪律

- **不回写 briefs/**：简报是派单方的单向输出；对简报有异议，写进回报或进度文件，不改原文。
- **回报以会话内回报为主**：改动清单、测试结果、输出摘录直接回给派单方；只有**产物类报告**（探索报告、评测报告、进度文件）才落 out/。
- **命名跟简报走**：简报指定了产物文件名就用它；未指定的衍生产物用「简报号-主题」或「主题-标识-日期」等可排序命名。
- **长战役配进度文件**（out/ 内、简报指定名）：每个工作流一行状态（未开始/进行中/已完成/被卡＋一句话）＋环境事实＋阻塞请示区。遇疑似绕不开红线的情况，停下写进请示区等主控，不得自行变通。

## 五、验收独立成单

- 验收是**另一份简报**，验收人与执行人分离；验收人**只验不改**，一行代码都不动。
- 清单逐条给出：入口、操作步骤、预期结果；关键项必须含一次**真实端到端动作**（真点一次按钮、真走一遍流程），不能只看静态界面。
- **问题回路写明流向**：发现问题 → 写新简报（续编号，或原编号加 R 的复测简报）记现象/复现步骤/期望 vs 实际 → 投递给简报里写死的修复方（「这类问题归谁」预先分好）→ 修完复测，循环到全绿。
- 证据落 qa-evidence/，文件名带简报号；回报＝逐条结论＋证据路径。

## 六、投递与轮询

文件本身不产生通知——简报写好没人知道，报告写完也没人知道。两端各自解决：

- **派单**：编排器给目标 agent 发一句 prompt 指到简报：「读 briefs/NN-主题.md，严格按它执行；完成后按简报末尾的回报口径汇报。」
- **收货**：主控**定时拉取**——读 out/ 报告与进度文件、读执行方窗格输出；等状态翻转再看，不轮询刷屏。简报里明说「你不主动找我，我走拉取通道」，执行方完工不必找人。

## 七、交接文档（HANDOFF）

任务中途换人/换窗口时写 HANDOFF-<任务>.md，**自包含**：新接手者读这一个文件就能上手，不用找上一个窗口。固定六段：

1. 你是谁、现在局面在哪（真值源文件清单）
2. 已拍板的决定，别再问
3. 第一步做什么（带可直接执行的命令）
4. 验收标准（不达标就打回）
5. 继承纪律（违反即返工）
6. 已做过的事，别重复劳动
