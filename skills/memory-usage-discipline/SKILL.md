# memory-usage-discipline：agent 长期记忆使用纪律

接了记忆工具的 agent 有两类典型失败：检索端乱搜（跳过路由全库大海捞针、重复拉取），写入端乱写（流水账入库、绕过容量控制、操作失败还谎报成功）。本 skill 给出一段参数化的纪律文本：替换占位符后可直接放进 system prompt、规则文件或任务卡。

## 一、纪律文本（替换 <占位符> 后照抄）

```text
把 <memory_system> 当作唯一的持久个性化记忆。
每个新会话开始时，调用一次 <hot_context_tool>。
当过去的上下文可能相关时，先调用 <route_tool>，然后只搜它明确返回的一到两个记忆库——
用 <search_tool> 检索，带上 <route_tool> 返回的路由决策 ID，检索模式用 <hybrid_mode>。
只有热点图不清楚时才查 <index_channel>；显式全库搜索（<full_search_tool>）只作为最后手段。
只保存持久的事实、偏好、决策、约束、目标和可复用知识。
标签永远不直接创建知识图谱的节点或边。
绝不把普通知识写进 <index_channel>，绝不省略 <scope_param>（目标库参数），
绝不绕过容量控制，绝不把不可用的操作说成已成功。
```

## 二、逐条解释

**单一记忆源。** 持久个性化记忆只认一个系统；不在本地文件、会话摘要、第二套工具里另存「影子记忆」。两套记忆必然分叉，分叉必然互相污染。

**会话开始拉一次热上下文。** <hot_context_tool> 每会话恰好一次：不拉就缺全局图，反复拉是浪费且会用陈旧快照盖掉会话中已获得的新信息。

**先路由后定向搜。** 检索默认路径是 <route_tool> → 只搜它点名的一到两个库，并带上路由决策 ID，让每次检索可回溯「当时为什么搜这里」。禁止跳过路由直接撒网——那会把检索成本和噪音同时放大一个量级。

**降级序。** 路由定向搜（默认）→ 索引通道（仅当热点图不清楚、需要重新定位时）→ 显式全库搜索（最后手段，用了要能说出为什么前两级不够）。

**只存持久知识。** 入库门槛：事实、偏好、决策、约束、目标、可复用知识——都是「下个月还成立」的东西。不存流水账：操作日志、一次性中间结论、对话内容的复述都不入库。

**结构由系统管。** 打标签是给检索用的；标签本身永远不直接生成知识图谱的节点或边，图结构由记忆系统自己的管线决定。

**容量与诚实。** 不绕容量控制：容量满时按系统的淘汰/合并机制走，不硬塞、不另开旁路。记忆操作不可用或失败时如实报告，绝不声称成功——虚报一次，下游所有依赖记忆的判断都被污染。

## 三、占位符映射表（示例值：MemOS）

| 占位符 | 含义 | MemOS 示例值 |
|---|---|---|
| `<memory_system>` | 记忆系统名 | `memos-local`（MCP server） |
| `<hot_context_tool>` | 拉热上下文/全局热点图 | `get_hot_context` |
| `<route_tool>` | 记忆路由（返回该搜哪几个库＋路由决策 ID） | `route_memory` |
| `<search_tool>` | 定向搜索 | `search_memories` |
| `<hybrid_mode>` | 检索模式参数 | `search_mode: "hybrid"` |
| `<index_channel>` | 索引/热点图通道 | `index` 库 |
| `<full_search_tool>` | 显式全库搜索 | `search_all_memories` |
| `<scope_param>` | 目标库参数 | `cube_ids` |
| `<write_tool>` | 写入/续写 | `add_memory` / `update_memory` |

接其他记忆系统（mem0、zep、自建）时重写这张表即可，纪律文本不变；某占位符无对应物时，删掉涉及它的整句，不要留空话。

## 四、可选加严：回合节奏

高强度协作会话可以约定：**每个用户回合至少一读一写**——回合开始检索一次相关记忆，回合结束把有效进展写回（优先用 <write_tool> 续写既有条目，而不是新建）。注意这是**场景化加严**而非通用默认：低频或一次性任务照此执行只会制造流水账，恰与「只存持久知识」冲突。出处为 Papertable 协作口径（HANDOFF-PW-63 §5）。
